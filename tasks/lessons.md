# Lessons

## L-001 Tesseract の日本語 PDF は「1文字ごとの空白」で検索不能になる
- 事象: `pytesseract.image_to_pdf_or_hocr()` が作る日本語 PDF は、テキスト層が
  `<8FFD0020>`（文字＋空白）の連続になり、`Ctrl+F` で「追加実装」を検索しても 0 件になる。
- 効かない対処: `-c preserve_interword_spaces=1`、`--psm 6`（実測で改善せず）。
- 有効な対処: 生成直後の PDF の描画命令から、日本語だけの単語の末尾の空白(0020)を削る。
  さらに、次の文字までの距離に対して文字幅が極端（2.5倍超/0.4倍未満）な場合だけ Tz を補正する。
  全文字を一律補正すると逆にヒット数が減るため、異常時のみ補正するのが最良だった。
- 教訓: OCR PDF は「作れた」で終わらせず、**実際に検索できるか**を検証するまでが完了。
  検証は PDF ビューアと同じ仕組み（PyMuPDF の `search_for`）で行う。

## L-002 日本語 OCR は「縦書きの本」で完全に破綻する
- 事象: 縦書きの書籍を `-l jpn` で OCR すると、本文が「りり地や談る」のような文字化けになる。
  それでも PDF は正常に作られ、検索も「ヒットする」ため、テストの通し方によっては見逃す。
- 対処: `-l jpn_vert --psm 5` を使う。判定は `image_to_data` の平均確信度で可能
  （実測: 縦書きページ = 横書きモデル 47 / 縦書きモデル 93、横書きページ = 93 / 44）。
- 教訓: OCR の検証は「検索がヒットするか」だけでは不十分。**読める日本語になっているか**を
  実際の本文サンプルで目視確認する。自動テストの合格が品質の合格とは限らない。
