# kindle-Notebook-LM

Kindle for PC の書籍を **ページ画像として連続キャプチャ** し、それを **OCR（文字認識）付きの PDF** にまとめるための Windows 用ツールです。

できあがる PDF は「見た目は Kindle の画面そのまま／中身は文字データ入り」なので、次のことができます。

- PDF 内を `Ctrl + F` で日本語検索できる
- 本文をマウスで選択・コピーできる
- ChatGPT や NotebookLM にアップロードして中身を読ませられる

---

## 普段の使い方（ダブルクリックだけ）

Windows のエクスプローラーでこのフォルダを開き、目的のファイルを**ダブルクリック**するだけです。

### 1. 本を 1 冊取り込む（キャプチャ → PDF まで自動）
- 右矢印キーでページが進む本 → **`Kindleキャプチャ_右矢印.bat`** をダブルクリック
- 左矢印キーでページが進む本 → **`Kindleキャプチャ_左矢印.bat`** をダブルクリック

キャプチャが終わると、**そのまま続けて OCR して `書籍名.pdf` まで作ります**。
普段はこれだけで完結します。

> 横書きの本はたいてい「右矢印」、縦書き（漫画・小説など）はたいてい「左矢印」で進みます。
> うまく進まなかったら、もう片方を試してください。**設定ファイルを書き換える必要はありません。**

### 2. あとから PDF だけ作り直す
`OCR_PDF作成.bat` をダブルクリック

保存先フォルダ（既定は `C:\kindle_ss`）を全部見て、**PDF がまだ無い本だけ**を PDF 化します。
過去に撮りためた PNG をまとめて PDF にしたいときや、
キャプチャだけ終わって PDF を作れなかったときに使います。

いずれの画面も、終了時やエラー時にすぐ閉じないようになっています。
エラーが出たときは、その画面をスクリーンショットして相談してください。

---

## 全体の流れ

```text
Kindle for PC
    ↓  Kindleキャプチャ_右矢印.bat / 左矢印.bat  （kindless.py）
C:\kindle_ss\書籍名\001.png, 002.png, 003.png ...
    ↓  そのまま自動で続行（marge_pngs.py → Tesseract OCR）
C:\kindle_ss\書籍名\書籍名.pdf  （検索できる PDF）

※ PDF だけ作り直したいときは OCR_PDF作成.bat（PDF が無い本だけ処理）
```

## 初回セットアップ（最初の 1 回だけ）

### 1. Python

Python 3.9 以上（動作確認は 3.10）。インストール時に
**「Add python.exe to PATH」に必ずチェック**を入れてください。

### 2. Python ライブラリ

このフォルダで、コマンドプロンプトから次を 1 回実行します。

```bash
pip install -r requirements.txt
```

個別に入れる場合は次と同じです。

```bash
pip install pytesseract pymupdf pillow natsort pyautogui opencv-python numpy wxPython
```

### 3. Tesseract OCR（文字認識の本体・**日本語データが必須**）

OCR を行う本体プログラムです。Python ライブラリとは別に、Windows へインストールします。

1. [Tesseract at UB Mannheim](https://github.com/UB-Mannheim/tesseract/wiki) から
   Windows 用インストーラー（`tesseract-ocr-w64-setup-…exe`）をダウンロードします。
2. インストーラーを実行し、**「Choose Components」の画面で
   `Additional language data` を開き、`Japanese` にチェック**を入れます。
   （英語 `English` は既定で入っています。両方使います）
3. インストール先は既定の `C:\Program Files\Tesseract-OCR` のままで構いません。
   PATH に登録されていなくても、このツールが自動でこの場所を探します。

**確認方法**: `OCR_PDF作成.bat` をダブルクリックして
「Tesseract OCR が見つかりません」「日本語言語データ『jpn』が見つかりません」が
表示されなければ、セットアップは完了です。

### 4. 保存先フォルダ

キャプチャ画像の保存先は `kindless.ini` の `base_save_folder`（既定 `c:\kindle_ss\`）です。
`marge_pngs.py` もこの設定を読むので、変更してもここ 1 か所を直すだけで済みます。

## コマンドから実行する場合

`.bat` を使わず、従来どおりコマンドでも実行できます。

```bash
# キャプチャ（kindless.ini の nextpage_key に従う：従来どおりの動作）
python kindless.py

# キャプチャ（その場だけページ送りキーを指定。ini は書き換わりません）
python kindless.py --direction right
python kindless.py --direction left

# キャプチャ後、その本だけ続けて OCR して PDF を作る（.bat と同じ動作）
python kindless.py --direction right --ocr

# 別の設定ファイルを使う（従来どおり）
python kindless.py my_settings.ini

# OCR 付き PDF を作成
python marge_pngs.py
```

## キャプチャ機能の使い方（詳細）

### 全画面について

スクリプトが Kindle を前面に出し、**必要なときだけ F11 を押して全画面にします**
（すでに全画面ならそのまま進みます）。事前に全画面にしてもしなくても構いません。
ただし**最小化していると見つけられない**ので、画面に表示された状態にしておいてください。

### 手順

1. **Kindle for PC で取り込みたい本を開く**（ウィンドウ表示のままで OK）
2. `Kindleキャプチャ_右矢印.bat`（または `_左矢印.bat`）をダブルクリック
3. ここから先はスクリプトが自動でやります
   - Kindle を前面に出す
   - `Ctrl + G` → `1` で **1 ページ目にジャンプ**
   - **F11 を押して全画面にする**
4. **書籍名を入力するダイアログが出ます。**
   - **本のタイトルを入力**してください。新しい Kindle アプリ（Microsoft Store 版）は
     ウィンドウタイトルに書名を持たないため、自動では入りません。
     空のままだと日付がフォルダ名になります
   - 念のため **Kindle が全画面になっているか目視で確認**（なっていなければ手動で F11）
   - （`+書籍名` と入力すると既存フォルダへの追記になります）
5. OK を押すと 3 秒後にキャプチャが始まります
6. `C:\kindle_ss\書籍名\` にページ番号付きの PNG が保存されます。
   コミックの場合はトリミングとグレースケール変換が自動で適用されます。
7. 最終ページに達すると自動で終了します
8. **そのまま OCR に進み、`書籍名.pdf` ができたら完了です**
   （OCR 中は画面もキーボードも使わないので、パソコンを普通に使えます）

### ⚠️ キャプチャ中はパソコンを触らないでください

**画面全体を撮影し、キーボードで Kindle のページを送る**仕組みのため、途中で他の操作をすると失敗します。

| やってしまうと | どうなるか |
| --- | --- |
| 他のウィンドウをクリックする | ページ送りキーがそちらへ行き Kindle が進まなくなる → **約 5 秒後に「最終ページ」と誤判定して途中で終了** |
| 他のウィンドウで作業を続ける | 画面が変わり続けるため、**その画面がページとして保存され続ける**（終了判定もされない） |
| 通知ポップアップが出る | その通知がページに写り込む（集中モードを ON にしておくと安全） |
| マウスを動かすだけ | 問題なし（マウスカーソルは写りません） |

数百ページだと 10 分以上かかります。**離席するか、別のパソコンで作業してください。**

- **止めたいとき**：Kindle を閉じるとスクリプトも止まります（コンソール画面で `Ctrl + C` でも可）。
- 途中で終了してしまったら、タイトル入力欄に `+書籍名` と入れて実行すると続きから追記できます。
- **ページ送り方向**：横書きの技術書は「右矢印」、縦書きの本は「左矢印」が多いです。
  数ページ進んでも同じページばかり保存されるときは、もう片方の `.bat` を試してください。
- **撮り直すとき**：同名フォルダは上書きされます。途中から足したい場合はタイトル入力欄の
  先頭に `+` を付けてください（例: `+新訂 孫子`）。
- Kindle ウィンドウが見つからない場合はエラーダイアログが出ます。
  `kindless.ini` の `window_title` と `execute_filename` を確認してください。

### 主な設定項目（`kindless.ini`）

- `nextpage_key`: ページ送りキーの既定値。`.bat` から起動した場合はそちらが優先されます。
- `capture_wait`: ページ送り後にキャプチャするまでの待ち時間。取りこぼす場合は長くします。
- `trim_after_capture`: コミック向けの余白トリミングを有効化します。
- `grayscale_threshold`: 白黒ページをグレースケールで保存する判定のしきい値。
- `base_save_folder`: 画像と PDF の保存先。書籍ごとにサブフォルダが作られます。

## OCR PDF 作成の仕様（`marge_pngs.py`）

- 保存先フォルダ内の**書籍フォルダごと**に `書籍名.pdf` を作成します。
- ページは `001.png, 002.png, … 010.png` のように**数字の順**で並べます。
- OCR 言語は `jpn+eng`（日本語＋英語）。`eng` が無い環境では自動的に `jpn` のみになります。
- **ページの周りの黒帯は自動で切り落とします。** 縦長のページを横長の画面で撮ると
  左右に黒い帯ができますが、帯が付いたままだと Tesseract のレイアウト解析が失敗し、
  ページによっては 1 文字も読めなくなります（実測: 0 文字 → 1,939 文字）。
  本の全ページを見て共通の範囲を決めるので、ページの大きさは揃ったままです。
- **小さく表示されたページは 2 倍に拡大して OCR します。** 文字が小さいと精度が落ちるためです
  （実測: 517 文字 → 1,079 文字、「代暁案」→「代替案」）。
  PDF に入れる画像は元の大きさに戻すので、容量は増えません（むしろ少し減ります）。
- **横書き / 縦書きは本ごとに自動判定します。** 本の中ほどのページを 2 枚試し読みし、
  読み取りの確からしさが高い方（横書き `jpn` / 縦書き `jpn_vert`）で 1 冊を通して OCR します。
  実行時に `書き方向の判定: 横書き 46.8 点 / 縦書き 92.7 点 → 縦書きの本として OCR します`
  のように表示されるので、判定結果はその場で分かります。
- **元のページ画像はそのまま残し**、その上に見えない文字データ（テキストレイヤー）を重ねます。
- 1 ページずつ処理するので、数百ページの本でもメモリを使い切りません。
- 進捗は `OCR 12/312 : 012.png` のように表示され、最後にページ数と処理時間が出ます。
- 処理時間の目安は **1 ページあたり約 2〜3 秒**（314 ページで約 11 分）。
  黒帯があって拡大処理が入る本は 1 ページ約 3〜4 秒になります。
  OCR 中は画面もキーボードも使わないので、パソコンは普通に使えます。
- PDF の容量は元 PNG と同じくらいです（例: 314 ページ＝ PNG 126MB → PDF 102MB）。
  詳しくは下の「PDF の容量とアップロード上限」を参照してください。
- Tesseract は日本語を 1 文字ずつ区切って PDF に書き込むため、そのままだと
  「追 加 実 装」となって `Ctrl+F` で「追加実装」を検索できません。
  本スクリプトはこの余分な空白を自動で取り除いてから保存します（実測で 12/12 語が検索可能）。
- **既に `書籍名.pdf` がある本はスキップします**（勝手に上書きしません）。
  作り直したいときは、その PDF を手で削除してから実行してください。
- OCR 対応より前に作った PDF（文字データが入っていない PDF）は、実行時に
  「※この PDF には文字データがありません」と表示され、最後に一覧でまとめて出ます。
  検索できるようにしたい本は、その本のフォルダにある PDF を削除してから
  `OCR_PDF作成.bat` をもう一度実行してください。
- 途中の 1 ページでも OCR に失敗したら、その本は PDF を作らずエラー表示にします
  （ページ抜けの PDF が黙って出来上がるのを防ぐため）。

### PDF の容量とアップロード上限

OCR 後の PDF は、元の PNG と同じくらいの容量になります（例: 314 ページ＝ PNG 126MB → PDF 102MB）。
主なサービスのアップロード上限は次のとおりです（2026 年 9 月時点）。

| サービス | 上限 | 300 ページ級（約 100MB）の可否 |
| --- | --- | --- |
| NotebookLM | 200MB / 50 万語（無料・有料とも同じ） | ○ 通る |
| ChatGPT | 512MB / 200 万トークン | ○ 通る |
| Claude.ai | 30MB / 20 ファイル | × 通らない |

**画質を下げて軽くするのは効果がありません。** Kindle のスクリーンショットは「白地に黒文字」の
平坦な画像で、PNG（可逆圧縮）が非常によく効いています。JPEG は写真向けの方式なので、
変換すると**逆に容量が増えます**（実測: 品質 90 で +48%、品質 80 で +17%）。
解像度を下げれば 35% ほど減りますが、文字がぼやけるうえ Claude の 30MB には届きません。

Claude.ai に読ませたい場合は、圧縮ではなく**ページ範囲で分割**してください（30MB なら 90 ページ程度）。

> 補足: テキスト層は画像と独立しているため、仮に画像を圧縮しても**検索精度は一切変わりません**。
> 劣化するのは見た目だけです。

---

### 検索の精度について

OCR は完璧ではありません。次の点はあらかじめ理解しておいてください。

- **行をまたぐ語は検索に引っかかりません**（例：「画像も投…／…稿」）。PDF 共通の仕様です。
- **誤認識は残ります**（例：「ましょう」→「ましよょう」）。小さい文字・ルビ・図の中の文字で起きやすいです。
- 短い語ほどヒットしやすく、長い文ほど途中の誤認識で外れやすくなります。

「単語で当たりを付けて拾い読みする」「ChatGPT や NotebookLM に読ませる」用途には十分実用的です。
特定の本だけ精度が低い場合は、Kindle の**文字サイズを大きめ**にしてから撮り直すと改善します。

## 困ったときは

- **「Tesseract OCR が見つかりません」**
  → 上記セットアップ手順 3 の Tesseract 本体がまだ入っていません。
- **「日本語言語データ『jpn』が見つかりません」**
  → Tesseract は入っていますが、日本語データが未選択です。
  インストーラーを再実行し、`Additional language data` → `Japanese` にチェックして入れ直します。
- **「Python が見つかりません」**
  → Python を「Add python.exe to PATH」にチェックを入れて入れ直してください。
- **タイトルが「2026_09_12_16_14_11」のような日付になる**
  → 新しい Kindle アプリ（Microsoft Store 版）はウィンドウタイトルが `Kindle` 固定で、
  書名がどこにも出ないため自動取得できません。ダイアログに本のタイトルを手で入力してください。
  旧 `Kindle for PC`（タイトルが `〇〇 - 書名` の形式）では従来どおり自動で入ります。
- **全画面にならない / ページが送られない**
  → Kindle が最小化されていないか確認してください。表示中のウィンドウだけを対象にします。
- **Kindle ウィンドウを検出できない**
  → Kindle を起動して画面に表示したうえで、`kindless.ini` の
  `window_title` / `execute_filename` を確認してください。
- **ページが進まない / 同じページばかり保存される**
  → もう片方の矢印キー用の `.bat` を試してください。
- **OCR の精度が低い / 文字化けしている**
  → まず実行時の「書き方向の判定」を確認してください。縦書きの本が横書きと判定されると
  文字化けします。その場合は Tesseract の `Japanese (vertical)` データが入っているか確認します。
  → Kindle の文字サイズを大きめにしてからキャプチャすると改善することがあります。
