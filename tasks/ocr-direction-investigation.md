## 再測定方法

リポジトリをカレントディレクトリとして、次のPythonコードを実行すると、残存画像の判定を再測定できる。
Kindleの起動は不要で、画像・既存PDFには書き込まない。

```python
import os
from pathlib import Path
import marge_pngs as m

root = Path(os.environ["TEMP"]) / "claude"
folder = next(root.glob(
    "*kindle-Notebook-LM/bba1c7eb-35d8-4303-b4ce-b16c25ae31a8/"
    "scratchpad/verify_out/run"
))
pngs = m.pngs_in(folder)
assert len(pngs) == 10, "検証時と入力枚数が違います"
lang, vertical_lang = m.check_tesseract()
box = m.find_page_box(pngs)
assert m.detect_direction(pngs, lang, vertical_lang, box) == (
    "jpn_vert+eng", "--psm 5"
)
```

## 残る限界と今回変更しなかった理由

- **図表・英字のOCRは不十分。** 006/009の横向きの図表文字、005/007の横倒しのWhy/How、
  一部の漢字は誤認識する。本文の書字方向判定が正しいことと、混在する全領域が正確に読めることは別。
  これはページ内の領域別OCRなどを実画像で調査すべき別課題であり、今回直ったとは扱わない。
- `_mean_confidence()` は認識トークンの単純平均で、認識量を評価しない。これは潜在的な弱点だが、
  今回の誤報の原因ではない。認識量で重みづけする変更には別の再現画像と縦横の回帰検証が必要。
- 1冊で設定を固定する現在の方式には、横書きの注意書き・図表が混じる本で限界がある。
  また、今回の測定は34冊すべての既存PDFの精度を保証しない。
- `--direction` を無条件に書字方向へ変換すると、縦書き本の横書き注意書きにも縦用OCRを強制してしまう。
  今回の現物はその反例であるため、ページ送り方向による強制補正を追加しなかった。
- 実装もテストも無変更。`kindless.py` の検証済みキャプチャ処理と、課題2のキャプチャ範囲検出には触れていない。
