# Lessons

## L-001 Tesseract の日本語 PDF は「1文字ごとの空白」で検索不能になる
- 事象: `pytesseract.image_to_pdf_or_hocr()` が作る日本語 PDF は、テキスト層が
  `<8FFD0020>`（文字＋空白）の連続になり、`Ctrl+F` で「追加実装」を検索しても 0 件になる。
- 効かない対処: `-c preserve_interword_spaces=1`、`--psm 6`（実測で改善せず）。
- 有効な対処: 生成直後の PDF の描画命令から、日本語だけの単語の末尾の空白(0020)を削る。
  さらに、次の文字までの距離に対して文字幅が極端（2.5倍超/0.4倍未満）な場合だけ Tz を補正する。
  全文字を一律補正すると逆にヒット数が減るため、異常時のみ補正するのが最良だった。
- 教訓: OCR PDF は「作れた」で終わらせず、**実際に検索できるか**を検証するまでが完了。
  検証は PDF ビューアと同じ仕組み（PyMuPDF の `search_for`）で行う。

## L-002 日本語 OCR は「縦書きの本」で完全に破綻する
- 事象: 縦書きの書籍を `-l jpn` で OCR すると、本文が「りり地や談る」のような文字化けになる。
  それでも PDF は正常に作られ、検索も「ヒットする」ため、テストの通し方によっては見逃す。
- 対処: `-l jpn_vert --psm 5` を使う。判定は `image_to_data` の平均確信度で可能
  （実測: 縦書きページ = 横書きモデル 47 / 縦書きモデル 93、横書きページ = 93 / 44）。
- 教訓: OCR の検証は「検索がヒットするか」だけでは不十分。**読める日本語になっているか**を
  実際の本文サンプルで目視確認する。自動テストの合格が品質の合格とは限らない。

## L-003 「それらしい値」への無言フォールバックは、失敗を隠すうえに事故を生む
- 事象: Kindle アプリが Store 版に更新されウィンドウタイトルが `Kindle` 固定になり、
  書名の自動取得が失敗。しかしコードは黙って日付を入れるため、原因が分からなかった。
- さらに危険だったのは、日付を消して空欄で OK すると
  `osp.join(base, "")` が保存先フォルダ自体を指し、`shutil.rmtree` で全書籍が消える経路があったこと。
  「自動取得の失敗」→「ユーザーが手で消す」→「全消し」と自然につながる導線になっていた。
- 対処: 失敗時はダイアログで明示して手入力に誘導し、空入力は必ず日付フォルダにフォールバックさせる。
  あわせてフォルダ名決定を `resolve_folder_name()` に切り出してテスト可能にした。
- 教訓: 外部アプリのウィンドウタイトルなど**自分が制御できない前提**に依存する箇所は、
  失敗を握りつぶさず表に出す。特に「空文字がパス結合に流れる」経路は削除処理と組み合わさると致命的。

## L-004 「同じ名前のウィンドウ」を掴む処理は Z オーダー次第で結果が変わる
- 事象: 「全画面にならない」の原因は F11 が効かないことではなく、
  `EnumWindows` が最初に見つけたウィンドウを返す実装のため、
  **非表示のまま残っていた旧 Kindle for PC の Qt ウィンドウ**を掴んでいたこと。
  列挙順は Z オーダーなので実行のたびに掴む相手が変わり、再現しない不具合に見えた。
- 対処: `IsWindowVisible` / `IsIconic` で表示中のものだけに絞り、面積が最大のものを選ぶ
  (`GetVisibleWindowHandleWithName`)。正しいウィンドウなら F11 は問題なく効くことを実測で確認。
- 併せて: F11 はトグルなので、既に全画面なら押さない(押すと解除される)。
  ウィンドウ矩形と画面サイズの比較で判定する。
- 教訓: 「効かないキー」を疑う前に、**キーが届いている相手**を確認する。
  外部アプリの自動化は、まず対象ウィンドウの特定を疑うこと。
